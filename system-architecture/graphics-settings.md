# Graphics Settings Apply Chain

Runtime graphics toggles live in `src/graphics/`: `graphics_settings.rs` (enums/resources/defaults) + `apply_systems.rs` (insert/remove Bevy components). Settings UI is the Seasons-adjacent pages in `src/ui/ui_settings_system.rs`. Every settings page edits a clone of its resource and writes it back with `set_if_neq` (`edit_if_changed`), so an open but untouched window does not flag the settings changed every frame (which used to re-run every apply system while the window was open). Settings resources therefore derive `Clone + PartialEq`.

## Defaults vs opt-in

- Camera spawn defaults (`src/lib.rs`): `Tonemapping::TonyMcMapface` (RESTORED 2026-09-25 — the white film/flash was ColorGrading exposure on clamped HDR, not the tonemap pass; ColorGrading component + brightness/contrast/saturation/gamma fields + `apply_color_grading_system` + `TimeOfDayGrading` TOD tint are now DELETED), `Bloom { intensity: 0.15, ..NATURAL }` (on), `ScreenSpaceAmbientOcclusion` Medium (on), `Smaa` Ultra (on), `AutoExposure` with the shared `graphics::AutoExposureCurve` compensation curve (plugin added manually — `PostProcessPlugin` does not register it; see "Auto Exposure target" below), `ShadowFilteringMethod::Gaussian`, `VolumetricFog{steps: 64}`, `Msaa::Off`, `DirectionalLightShadowMap{size: 2048}`. DepthOfField and MotionBlur are NOT spawned (opt-in via settings).
- **Single-owner policy (2026-09-25):** Bloom/SSAO/SMAA/AutoExposure/MotionBlur/DOF components on the camera are toggled ONLY by the `GraphicsSettings` apply systems (write-on-change). `apply_post_processing_settings` (src/lib.rs) owns ONLY VolumetricFog. The PostProcessing page used to mirror bloom/SSAO toggles with remove/re-insert semantics; the two owners fought and each cycle recreated ViewTarget textures (stall/flash source). PostProcessingSettings keeps only `dof_enabled`/`volumetric_fog_enabled` fields; only the VF checkbox is wired. Camera components are also implicitly HDR because `Bloom`/`AutoExposure` have `#[require(Hdr)]`.
- TAA, SSR have no implementation in `src/`; do not document them as available.

## Auto Exposure target (2026-09-30)

- Bevy's AE shader computes `target = curve(avg) - avg`, where `avg` is the metered log2 scene luminance. The curve's y value is therefore the log2 luminance the scene average is driven to. Bevy's default curve is flat 0, which drives the average to 1.0 pre-tonemap (about 2.5 EV above middle grey). That is why the image was "very bright" with AE on, and it also lifted night up to daytime brightness.
- `GraphicsSettings::auto_exposure_target_ev` (default **-1.3**, tuned in-game 2026-09-30; Graphics tab > Effects > "Exposure Target", -4..=1 EV) sets that y value for daylight. `auto_exposure_compensation_curve` in `apply_systems.rs` is flat at the target for metered averages at or above -2 log2 luminance (daylight meters around -1). Below that it slopes down so AE compensates only 50% of the extra darkness, bottoming out at target - 3 EV at -8. The result is that night and caves stay darker than day.
- The `AutoExposureCurve` resource (created in `run_client` right after `AutoExposurePlugin`) holds one curve handle that is used at camera spawn and by `apply_auto_exposure_system`. The system rebuilds the asset in place (`Assets::get_mut`) only when the target value actually changes. The camera component keeps the same handle.
- Only affects the main camera. The water-reflection camera has no AE, so its exposure is fixed.

## Apply systems (`src/graphics/apply_systems.rs`)

- `apply_shadow_quality_system` (`:68`): `ShadowQuality::{Off,Low,Medium,High(default),Ultra}` → cascades 0/1/2/3/4, map size 0/1024/2048/2048/4096, distance 0/50/100/200/400; recomputes `CascadeShadowConfig{Bounds}` for the sun AND `MoonLight` (the moon casts shadows while the sun is down); skips `SkyFillLight`.
- `apply_tonemapping_system` (TonemappingMode includes `KhronosPbrNeutral`), `apply_bloom_system`, `apply_shadow_filtering_system` (Hardware2x2/Gaussian; writes the main CAMERA's `ShadowFilteringMethod`, since Bevy reads it from the camera; it used to query lights and was a no-op; `Temporal` removed because it needs TAA), `apply_ssao_system` (`:236`), `apply_smaa_system` (`:274`, Disabled/Low/Medium/High/Ultra), `apply_motion_blur_system` (`:318`), `apply_dof_enabled_system` (`:354`), `apply_fxaa_system` (`:379`), `apply_view_distance_system` (`:408`), `apply_texture_quality_system` (Low/Medium = sampler `lod_min_clamp` 2/1 on images with a mip chain, i.e. DDS game textures, which now load their mips; egui-registered images are never clamped. Default samplers are converted to the real global default (`ImagePluginDefaultSampler`, linear), not `ImageSamplerDescriptor::default()` (nearest). The clamp is shared with the DDS loader (`TextureLodMinClamp`) so later loads start with it, and Added/Loaded/Modified image messages are checked too. Only images whose sampler changes are `get_mut`'d. Materials capture samplers at prepare time, so after a settings change rewrote samplers, `refresh_materials_after_sampler_change` re-prepares the ROSE object/effect, standard and particle materials once on the next frame (`MaterialSamplersStale`)), `apply_ambient_light_system` (`:450`, `80.0 * multiplier` into `GlobalAmbientLight`).
- Round-trip truth for shadows/volumetrics/post defaults: [zone_lighting.md](zone_lighting.md), [Render.md](Render.md).
